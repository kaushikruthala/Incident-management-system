Incident Management System — Architecture

SRE-grade · 10 000 signals/sec · Debounce · Dual Persistence · Workflow Engine

Ingestion & Backpressure

  • • gRPC + HTTP dual protocol ingestion
  • • Token-bucket rate limiter (10 000/sec cap)
  • • Async ring buffer absorbs DB lag bursts
  • • Redis INCR debounce: 1 WorkItem per 10 s window
  • • 100 signals → 1 WorkItem, all linked via batch_id
  • • /health + 5-sec throughput console metrics

Persistence Design

  • • PostgreSQL: ACID WorkItems, RCA, state transitions
  • • GENERATED ALWAYS mttr_seconds column
  • • MongoDB: raw_signals + signal_batches, TTL 90d
  • • Redis ZSET: live dashboard feed, no Postgres hit
  • • TimescaleDB: signals/sec, p95 latency aggregations
  • • Immutable transition log (work_item_transitions)

Workflow & SRE Patterns

  • • State Pattern: OPEN → INVESTIGATING → RESOLVED → CLOSED
  • • Strategy Pattern: P0/P1/P2 alerting per component type
  • • RCA mandatory: CLOSED blocked if RCA incomplete
  • • MTTR auto-calc: first_signal_at → closed_at delta
  • • Retry logic with exponential backoff on DB writes
  • • Zero-downtime: ring buffer decouples all layers
